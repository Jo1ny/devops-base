# Права доступа в Linux (File & Directory Permissions)

## 1. Базовая математика прав
* `r` (read / чтение) = **4**
* `w` (write / запись, изменение) = **2**
* `x` (execute / запуск или вход) = **1**
* `-` (нет прав) = **0**

Сумма формирует цифру от 0 до 7:
* `7` = 4 + 2 + 1 (rwx: чтение, запись, исполнение)
* `6` = 4 + 2 (rw-: чтение и запись)
* `5` = 4 + 1 (r-x: чтение и исполнение/вход)
* `4` = 4 (r--: только чтение)
* `0` = --- (полный запрет доступа)

---

## 2. Триада субъектов (User, Group, Others)
Любая комбинация из трёх цифр определяет доступ для трёх уровней:

`chmod 640 secret.env`
* Первая цифра (`6` / `rw-`) -> **User (Владелец)**: создатель файла.
* Вторая цифра (`4` / `r--`) -> **Group (Группа)**: команда пользователей с общими правами.
* Третья цифра (`0` / `---`) -> **Others (Все остальные)**: любой сторонний юзер или сервис в системе.

---

## 3. Критическое отличие: Файлы vs Каталоги

| Право | Обычный файл | Директория (каталог) |
|---|---|---|
| **r (4)** | Читать содержимое (`cat`, `nano`) | Просматривать список файлов (`ls`) |
| **w (2)** | Менять/дописывать тело файла | Создавать/удалять файлы внутри папки |
| **x (1)** | Запускать как бинарник или скрипт | **Заходить внутрь (`cd`) и проходить транзитом по пути** |

> **Почему Nginx требовал `chmod o+x ~` при ошибке 403 Forbidden?**  
> Nginx работает под системным пользователем (например, `http`) и относится к категории *Others*. Чтобы добраться до файла сайта в `/home/user/site/index.html`, ядру Linux необходимо право `+x` на каждом каталоге в цепочке пути.

---

## 4. Золотые правила безопасности (DevSecOps)
* **Принцип наименьших привилегий:** давать только те права, без которых сервис не работает.
* **Стандартные права:**
  * Файлы конфигурации и статики: `644` (`rw-r--r--`).
  * Секреты, приватные ключи, .env с паролями: `600` (`rw-------`) или `640` (`rw-r-----`).
  * Каталоги: `755` (`rwxr-xr-x`).
* **Почему `chmod 777` — это дыра в безопасности:** любой сторонний процесс или атакующий через уязвимость в веб-приложении может перезаписать исполняемый файл или загрузить и запустить вредоносный скрипт (web-shell).
